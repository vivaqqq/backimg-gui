## 一、这个 DLL 本来是干嘛的（原版功能）

开源作者 Maple（winmoes.com，2021 年写的）做的这个小插件，只干一件事：

> **把文件夹窗口里那片白色背景，换成一张你喜欢的图片。**

它的工作方式：注册成资源管理器的加载项，在资源管理器画窗口的过程中"搭车"，
在白底铺完之后、图标文字画上去之前，把图片垫进去。所以图标、文件名都不受影响。

原版（DLL 自身版本号 1.1.0.1，221,696 字节）具备的功能：

| 功能 | 说明 |
|---|---|
| 文件夹窗口铺背景图 | 图片放在 `plugin\Image\` 目录（或面板里指定的自定义目录） |
| 多张图随机换 | 目录里放多张，每次开窗口随机挑一张 |
| 铺图方式与透明度 | 几种铺图定位方式（面板里切换）+ 图片透明度滑块 |
| 文件夹专属背景 | 给某个特定文件夹指一张专属图（面板"文件夹专属背景"页） |
| 文件对话框背景（folderExt） | 打开/保存文件的那个对话框也能铺图 |
| 只认两种图片格式 | **只有 .png 和 .jpg，别的格式一律不理** |
| 无任何日志 | 出了问题没有任何记录，只能瞎猜 |

配套的"backimg 图形板"面板负责改配置、注册/注销、重启资源管理器。

## 三、v1.3.16 新增：背景图等比缩放 + 实时跟随（功能大项）

这是整个修复线最大的一次功能升级。

**之前的问题**（v1.3.15 及原版都这样）：
图片按**原始像素尺寸**硬贴到窗口上——图比窗口大就直接溢出看不到全貌；
就算选"缩放"档，实际用的是最粗糙的最近邻插值放大，你的竖图放到全屏就是 2.5 倍，**满屏马赛克还会变形**。

**现在**（v1.3.16 起）：

| # | 新能力 | 对你的意义 |
|---|---|---|
| 1 | **七档显示位置全部等比缩放，绝不变形**（按你要求，最后一档"缩放并填充"保持原规则不变） | 人物、风景图不管放到多大，比例永远和原图一致，不会被拉胖压扁 |
| 2 | **窗口任意尺寸实时跟随**：拖动、最大化、全屏，图片跟着窗口等比变大变小 | 全屏也能铺满，不会超出窗口显示 |
| 3 | **高质量插值**（GDI+ 双三次） | 放大后平滑，不再是马赛克 |
| 4 | **缩放缓存** | 拖窗口时不重复计算，不卡 |
| 5 | **透明度完整保留** | 带透明背景的 PNG 依旧透明（实测与旧版 alpha 逐位一致） |

**七档语义速查**（面板"图片显示位置"那排按钮）：

| 按钮 | 行为 |
|---|---|
| 左上 / 右上 / 左下 / 右下 / 居中 | 图片放得下就按原始尺寸摆（小图不放大成糊图）；**放不下自动等比缩小，不再溢出窗口** |
| **缩放** | **整图等比完整适配窗口，随窗口实时放大缩小**（四周可能留白）——想让图跟着窗口变就选这个 |
| 缩放并填充 | 等比铺满窗口并居中裁掉溢出（与原行为一致，未改动） |

> 注意：「缩放」档的语义相对老版变过——老版的"缩放"是**拉伸填满（会变形）**，
> v1.3.16 起改成**等比完整适配（不变形，可能留白）**。想铺满不留白用"缩放并填充"。

## 四、v1.3.17 修了什么（v1.3.16 引入/暴露的问题，对使用者可感知的）

| # | 问题 | 修复后 |
|---|---|---|
| 1 | **内存无限增长**：每换一次图片目录，资源管理器永久多驻留约 177MB | 残留有界（39 张图约 66MB 恒定），反复换目录零增长 |
| 2 | **一个会让 explorer 崩溃的雷**：线程缓存挂在 Windows 的线程局部存储上，MinGW 编译器在线程退出时会在已释放的内存上跑它的析构函数——窗口线程一退出就可能崩 | 彻底改为手动生命周期管理，窗口关闭即释放 |
| 3 | **图片目录为空/文件损坏时 CPU 跑满**：每一帧都自触发重绘（实测 1000/1000 帧） | 收敛到 1 次 |
| 4 | **GDI 句柄累积耗尽**：反复开关窗口后句柄撞上 10000 上限，背景画不出来 | 死线程缓存自动清扫，句柄有界、不单调增长（实测数百到约 1300 锯齿波动） |
| 5 | 坏文件会被真正送进解码器（v1.3.16 的一个新暴露面） | 轻量图片头解析先行把关：确证损坏才拒收，看不懂的交给系统裁决——**不会误杀正常图片**（你的 39 张图全数通过） |

另有界面小修正：面板显示的 DLL 版本号补齐为 1.3.17（v1.3.16 漏改成了 1.3.15）。

## 五、v1.3.18 修了什么（千问审计核验后，对使用者可感知的）

v1.3.17 交付后用千问 3.8 Flash 对 DLL 源码扫了一轮内存安全审计，我们逐条对照源码核验：
属实的修掉，不属实的书面驳回（驳回理由全文见变更清单，这里如实记录）。

| # | 问题 | 修复后 |
|---|---|---|
| 1 | **GDI 句柄泄漏的漏网之鱼**：缩放结果在一个少见的失败分支会漏掉一个句柄；句柄紧张时命中后背景必然画不出来（故障自锁） | 已修，失败路径全部释放干净 |
| 2 | **换图集后缓存全部白算**：增删图片文件导致列表重建时，缩放缓存的"钥匙"跟着对象换新，所有线程白重算一轮 | 缓存改按**图片内容**寻址——同一张图不管列表怎么重建都照常命中（自检实测：重建后内存零增长） |
| 3 | **DLL 卸载路径的死锁/悬垂指针隐患**：卸载清理代码在系统最敏感的时机拿锁、删别的线程正在用的缓存 | DLL 钉死在进程里随进程退出收尾（外壳扩展的常规做法），危险的清理代码整段移除 |
| 4 | **COM 层两处原版就有的老雷**：工厂对象引用计数写错行（每次增删净涨 1）；卸载约定调用 SetSite(NULL) 时会空指针崩溃 | 都已修；修计数时特意避开了"直接改一行会崩静态对象"的陷阱（工厂改为正规堆分配） |

界面改动：**移除状态栏「已提权/未提权」胶囊**——它显示的是面板进程自己的管理员状态，
静态不变、与 DLL 注册状态无关，紧挨"DLL 未注册"极易误导，已删除。

另外如实说明：千问报告里标为"全包最严重"的 P0-1（跨线程销毁缩放句柄），经逐行核验
**机制不成立**——缓存是每线程私有的，别的线程根本拿不到你线程缓存里的条目，未修；
但它连带牵出的卸载路径真问题（上面第 3 条）确实存在，已一并修掉。

## 七、v1.3.20 做了什么（随机功能重做，对使用者可感知的）

用户反馈"总觉得不太随机"，核验确认三个真实成因，全部修掉，另按需求加了定时轮换：

| 对使用者的意义 | 做了什么 |
|---|---|
| 重启后"随机"不再是同一条序列 | 旧版随机种子只精确到秒，explorer 秒级重启会逐字复现上次的"随机"结果；换成高质量随机源（梅森旋转 + 系统熵源混种），实测 41 档×4 万次分布均匀、8 线程 16 万次零越界 |
| 多标签/多窗口各自独立抽签 | 旧版同一线程开第二个标签会顶掉第一个标签的记录——两个标签画同一张图（"不随机"观感主因之一）；现在每个窗口各自记账，互不覆盖 |
| 新功能：定时轮换 | 面板 random 行右侧选间隔（不轮换/1/2/5/10/30 分钟/自定义整数分钟），每个文件夹窗口每隔 N 分钟独立换一张随机图；默认"不轮换"，升级后行为照旧 |
| 非法值零危害 | randomMin 只认整数分钟（输入框根本输不进小数点），越界自动钳位到 1 天，配置文件按不可信输入兜底处理 |

## 七·五、v1.3.25 做了什么（秒级轮换 + 自定义目录自愈，对使用者可感知的）

### ① 定时轮换支持秒钟（你提的红/绿框需求）

| 改动 | 说明 |
|---|---|
| 自定义时间框收窄 | 输入框缩到只容数字（最多 5 位：86400），把位置让给新增的单位框 |
| **新增「分钟/秒钟」单位下拉** | 在输入框后面（绿箭头位置），选了秒钟就能填 10、30、90 这样的秒数——图片轮换间隔完全自由 |
| 配置键升级 | `randomVal`（秒）为权威键；老键 `randomMin` 自动兼容读取、保存时仍同步写入 |
| 单位切换规则 | 切到"分钟"时如果填的不是整分钟（比如 90 秒），会自动取整到分钟并在日志里说明；"秒钟"档永远精确 |

### ② 自定义图片目录"偶发不显示"修复（你实机报的 bug）

**现象回顾**：把目录设到 `G:\手机备份\Image` 偶尔整窗没背景；设回程序目录 Image 又好了；
再设回 G: 又好了——不是必然，是偶然。

**根因**：目录"存在"（系统查得到它）不等于"此刻能列出里面的文件"。磁盘未就绪
（移动硬盘刚唤醒、重启后卷延迟挂载）、杀软瞬时锁目录时，枚举会瞬间全部拿不到句柄，
旧版这时直接判"没图"并清空背景，**之后没有任何自动补救**——只有碰巧开新窗口才可能重试。

**修复后（三层）**：

| 层 | 做了什么 |
|---|---|
| 路径规整 | 目录尾部多余的 `\`、引号、空格自动清理，手改 ini 也不会歧义 |
| 瞬时重试 | 目录在但列不出内容 → 立刻原地重试几次（真·空目录不受影响，不拖慢开窗） |
| **自动自愈** | 还不行就每 3 秒自动重载一次，目录一恢复，**已开的窗口不用重开，背景自动回来** |

## 七·九、v1.3.29 做了什么（首次打开卡顿根治，DLL 大版本升级）

这一版面板界面**一个字都没变**（只有版本号），全部功夫花在 DLL 内部 —— 解决
"电脑开机后，第一次打开任何文件夹窗口都要卡 1~2 秒"这个老大难。

**对使用者可感知的变化：**

1. **开机后第一次打开文件夹不再卡顿**。旧版把整个图片库完整读进内存才肯画
   第一扇窗（148 张大图 ≈ 1.85GB 读取）；新版改成后台线程只读每个文件的
   "头部 256KB"（合计约 38MB），界面线程绝不等待 —— 窗口秒开。
2. **内存占用大幅下降**。旧版把全部图片常驻内存（你的图库 ≈ 1.85GB）；
   新版改成"画哪张才读哪张"，省下的内存约等于你整个图片库的体积。
3. **坏图自动拦截，且拒绝有据可查**。传输中断产生的"半张图"（显示成上半
   正常下半黑边）以前会混进轮换；现在进入轮换前就被拦下，并且每拦一张都在
   `plugin\ExplorerBgTool_init.log` 记一行 `[扫描剔除]`——哪张图没出现，
   打开日志就能对上号。
4. **动态照片（Motion Photo）正确支持**。手机拍的"动态照片"其实是一个
   .jpg 后面拖着一段 MP4 视频，新版能识别这种结构，不会被误判为坏文件，
   正常参与轮换（显示静态画面）。
5. **同名换图即时生效**。替换图片文件（同名覆盖）后，下一次轮换就显示新图，
   不用再重启资源管理器。

**技术明细与六轮模型审计记录**：见 `DLL源码\变更清单_CHANGELOG_v1.3.29.md`
（含 R2~R6 修订）与总卷第十九章。

## 十一、怎么确认电脑上现在跑的是哪一版

打开 `plugin\ExplorerBgTool_init.log`，看第一行：

- `v1.3.29` → 现行版在跑
- `v1.3.28` → 旧版（功能一致，但有首次打开卡顿与高内存问题，建议升级）
- `v1.3.25` / `v1.3.26` / `v1.3.27` → 更旧版（仅界面细节差异）
- `v1.3.15` / `v1.3.16` / `v1.3.17` 或没有这行 → 旧版或原版在跑

回退方法：把旧版 DLL 覆盖回去、重启资源管理器即可，配置文件不用动
（桌面保留了 v1.3.15 ~ v1.3.27 十三套完整旧包，含各自的 DLL）。
